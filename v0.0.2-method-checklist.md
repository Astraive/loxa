# Loxa v0.0.2 Method Checklist

Source-backed verification of the public SDK and platform surface as implemented in this repo on 2026-05-23.

## Canonical rules

- Official examples should import and use only `loxa`.
- Custom clients created via `createLoxa` / `create_loxa` / `CreateLoxa` are optional advanced APIs.
- Alias names are user-defined. No exported singleton other than `loxa` should be presented as the default mental model.
- Public status is determined from exported entrypoints and routable handlers, not from internal symbols or older aspirational manifests.

## Entrypoints verified

- JS/TS: `sdks/js/src/index.ts`, `sdks/js/src/loxa.ts`, `sdks/js/package.json`
- Python: `sdks/py/src/loxa/__init__.py`
- Go: `sdks/go/loxa.go`
- Rust: `sdks/rs/src/lib.rs`
- Collector: `collector/server/http/server.go`, `cli/internal/commands/sinks.go`, `cli/internal/client/collector.go`
- Cortex: `cortex/internal/api/server.go`

## Platform split

- `collector` is the public ingest, query, tail, delete, DLQ, replay, schema, and sink-control plane.
- `cortex` is the public reconstruction, graph, remediation-feedback, GraphQL, and WebSocket intelligence plane.
- SDKs are collector-first client libraries with meaningful local lifecycle, timing, sampling, redaction, sink, and testkit behavior.

## Module-only exports

These features exist, but they should not be documented as root `loxa` helpers.

| Family | Public status | Evidence |
| --- | --- | --- |
| JS framework middleware | Subpath exports such as `loxa-js/middleware/express` | `sdks/js/package.json` |
| Python middleware | Module exports under `loxa.middleware.*` | `sdks/py/src/loxa/middleware/*` |
| Go middleware | Subpackages under `sdks/go/src/middleware/*` | `sdks/go/src/middleware/*` |
| Rust middleware | Module exports under `loxa::middleware::*` | `sdks/rs/src/middleware/*` |

## Root-surface mismatches that docs must avoid

- JS/TS helper constructors such as `string`, `int`, `money`, and `userId` are package exports, not methods on the default `loxa` instance.
- Python should be documented as `import loxa`; the package module is the facade.
- Go package-level `Info`, `StartEvent`, `Set`, `Finish`, and `Emit` should lead the docs. Factories remain secondary.
- Rust intentionally does not re-export the `Logger` type. Public guidance should use `loxa::default()`, `loxa::create_loxa(...)`, `loxa::alias(...)`, and `loxa::start_event(...)`.

## Still non-uniform or not universal

These should be treated as partial parity or target-surface items rather than shipped-everywhere APIs.

- `development(service)` is not present across all SDKs.
- `fromEnv()` is not present at Go root parity.
- `withEndpoint(url)` is not a universal public root API.
- `withRedaction(policy)` is not a universal public root API.
- HTTP/framework helper names like `expressMiddleware`, `djangoMiddleware`, `goHTTPMiddleware`, `axumLayer`, and `towerLayer` should be documented as module/subpackage integrations, not root methods.
- Sink helpers like `httpSink(config)` remain target-surface items unless verified at root.

## Documentation contract going forward

- Lead every SDK quick start with `loxa`.
- Keep factory and alias examples secondary.
- When staying `loxa`-only in JS/TS docs, prefer `set`, `merge`, and lifecycle methods over pretending helper constructors live on the default instance.
- Separate:
  - implemented at root `loxa` surface
  - implemented via module or subpackage
  - internal only
  - not implemented
